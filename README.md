# 서점 3사 베스트셀러 보고 시스템

교보문고·예스24·알라딘의 **주간 종합**과 **일간** 베스트셀러(각 1~100위)를 매일 아침 모아서
웹페이지로 보여 주고, 평일 아침 9시 전에 '주목할 책'과 상승 원인을 정리한 보고서를 메일로 보냅니다.

- 순위 웹페이지: https://editor-taek.github.io/bookrank.taek/
- 사양서: claude.ai 프로젝트 「김정택_홍보」의 `bestseller-report-spec.md`

## 어떻게 돌아가나요

| 순서 | 무엇이 | 언제 | 하는 일 |
|---|---|---|---|
| 1 | 깃허브 액션 (`.github/workflows/collect.yml`) | 매일 06:50, 07:35 (한국 시각) | `scraper.py`로 6개 순위를 모아 `data/`에 저장 |
| 2 | 깃허브 페이지 (`index.html`) | 항상 | `data/latest.json`을 읽어 순위표 표시 |
| 3 | Claude 예약 작업 | 평일 08:30 무렵 | `report_data.py`로 주목할 책·조사 대상을 고르고, 원인을 웹에서 찾아 메일 발송 |

## 파일

- `scraper.py` — 수집기. 서점별로 순위·제목·저자·출판사·서점이 표시한 순위 변동을 읽음
- `rules.py` — 주목할 책 기준 (1~10위 5계단↑ / 11~30위 10계단↑ / 31~100위 20계단↑)
- `report_data.py` — 보고서 재료 정리 (원인 조사 대상 고르기, 메일 표 만들기)
- `data/latest.json`, `data/latest.csv` — 오늘 순위
- `data/snapshots/날짜.json` — 날짜별 보관 (45일)
- `data/genre_cache.json` — 예스24·알라딘 책의 분야(청소년 여부) 기록. 한 번 확인한 책은 다시 확인하지 않음

## 규칙 메모

- 교보: 서점 데이터의 '지난 순위'로 변동 계산 (사이트 표시와 같음). 분야가 '청소년'이면 [청소년].
- 예스24: 목록에 표시된 ▲▼/NEW 그대로. 분야는 상품 상세페이지의 카테고리 경로로 판별.
- 알라딘: **목록에 순위 변동 표시가 없어서** 직전 수집분과 비교해 계산. 분야는 상세페이지로 판별.
- NEW(신규 진입)는 101위에서 올라온 것으로 계산 → 1~81위 신규 진입은 주목할 책.
- 교보 주간 종합은 주 1회 갱신. 갱신되지 않은 날은 '변동 없음'으로 처리.
- 음반·굿즈 등 책이 아닌 상품은 제외 (서점 순위 번호는 그대로 둠).

## 문제가 생기면

- 수집이 실패하면 보고서 맨 위에 '수집 실패'가 표시됩니다.
- 저장소의 **Actions** 탭 → '베스트셀러 수집' → **Run workflow** 버튼으로 다시 돌릴 수 있습니다.
- 서점이 페이지 구조를 바꾸면 `scraper.py` 수정이 필요합니다.
